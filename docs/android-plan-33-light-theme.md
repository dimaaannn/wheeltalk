# План 33. Светлая тема: документные экраны следуют системе

> «выглядит ужасно; пока не делаем, составь план». Делать только по его команде.

## 0. Что сломано и почему

Снимок владельца 13.08.2026: настройки в светлой системной теме. Фон окна и заголовок — светлые,
их красит тема (`SettingsTheme` = `Theme.MaterialComponents.DayNight`, values/styles.xml). А
карточки разделов, обводки, разделители, подсказки и служебные цвета прибиты **тёмными литералами
в коде**: в `SettingsCategoryActivity` тринадцать `static readonly Color` (`#282828` заливка
карточки, `#3A3A3A` обводка, `#9A9A9A` заголовок раздела, `#8A8A8A` подсказка, `#333333`
разделитель строк…). Итог — экран о двух хозяевах: половину красит система по теме, половину —
наши литералы по ночи. В тёмной теме этого не видно, потому и жило.

Это не «недокрашено», а известный грех «один рычаг — два хозяина» (план 29), только про цвет:
вопрос «какая сейчас тема» решает система, а вопрос «каким цветом карточка» — литерал, который
о первом вопросе не знает.

## 1. Граница: что следует системе, а что всегда тёмное

- **Всегда тёмные** — приборные поверхности: панель, «Цифры», плеер (та же панель), полосы
  тревоги, шторка (отдельное решение владельца 10.08.2026 — «шторка всегда тёмная»). Их не
  трогаем ни в одном шаге.
- **Документные** — следуют системной теме: настройки (корень и страницы, включая листы снизу и
  диалоги правки), «Поездки», «Данные», поиск колёс, экран «Что уйдёт» диагностики, диалоги
  общего назначения. У «Поездок», «Данных» и поиска литералов цвета нет (проверено grep
  13.08.2026) — они, скорее всего, уже живут по теме; правда проверяется глазами шагом 1.

## 2. Устройство: семантическая палитра одним источником

Ролями, а не цветами: `Surface`, `Card`, `CardBorder`, `RowDivider`, `TextPrimary`,
`TextSecondary`, `Hint`, `Accent`, `Override` (янтарь «своё»), `Link`, `Warning`, `Highlight`,
`DependantBar`. Каждой роли — два значения: день и ночь.

Источник — **ресурсы**: `values/colors.xml` + `values-night/colors.xml`, чтение из кода через
`ContextCompat.GetColor`. Почему ресурсы, а не класс с `if (uiMode)`: смену темы Android делает
пересозданием активности, и ресурсы переключаются сами — классу пришлось бы ловить конфигурацию
руками и обновлять уже построенные вьюхи. У панели палитра кодом (`DashboardOptions.Palette`) —
это не противоречие: панель всегда тёмная, ей тема безразлична.

Светлый набор не «инверсия», а подбор по контрасту: WCAG 4.5:1 для текста, 3:1 для крупного и
границ — тем же расчётом, что в шторке (план 25, там же прецедент замка).

## 3. Шаги

1. **Инвентаризация.** Все документные экраны и общие виджеты (`Ui/`, диалоги, листы снизу,
   чипы переходов): где литералы цвета, где цвет по теме. Итог — список мест перекладки.
2. **Палитра.** Роли из §2, оба набора значений, светлый — с расчётом контраста до внесения.
3. **Перекладка настроек** — основной объём: `SettingsCategoryActivity` (тринадцать литералов),
   корень настроек, редакторы значений, лист снизу, ряд «Где хранить», ярлыки слоя.
4. **Перекладка остатка** по списку шага 1.
5. **Замки:**
   - в документных активностях не остаётся `Color.ParseColor`/литералов — по исходникам, с
     белым списком всегда-тёмных файлов;
   - каждая роль палитры объявлена в обоих наборах (чтение обоих `colors.xml` тестом);
   - контраст расчётом для обеих тем — по образцу `QuickSheet`-замков плана 25.
6. **Гейты глазами на телефоне:** обе темы — пять страниц настроек, переход по ссылке с
   подсветкой, «Тестовые функции» (пунктирная карточка на снимке владельца была самой бледной);
   смена темы при открытом приложении — пересоздание не теряет позицию и смотровую область.

## 4. Чего не делаем

- Свой переключатель темы в настройках приложения — следуем системе; ручку заводить только по
  отдельному слову владельца (вопрос №2 ниже).
- Светлые варианты панели, «Цифр», шторки, плеера.
- Правку самих тем `styles.xml` — они уже DayNight и работают.

## 5. Вопросы владельцу — закрыты 13.08.2026

1. **Граница §1 подтверждена**: документные — по системе, приборные — всегда тёмные.
2. **Ручки темы не будет** — приложение следует системе.
3. **Акценты в светлом наборе темнить** — контраст по WCAG дороже побайтового равенства цветов
   между темами.
