# Телеметрия и BLE — константы среды

Вынесено 30.07.2026 из [плана 1](android-plan-1-base-app.md) (§2.1, §3.1, §5.1, §6): план стал
историческим, а эти четыре куска — единственное место, где записаны факты, не выводимые из кода.
Сверено с кодом на момент выноски; при расхождении верить коду и чинить здесь.

## Поток телеметрии

`WheelService` отдаёт снэпшоты Rx-потоком, а не событием:

```csharp
IObservable<TelemetrySnapshot> Telemetry { get; }
```

Правила, ради которых так:

- один механизм доставки — параллельного события нет и не заводится;
- время и планировщики во всех операторах — через `TimeProvider`/явный `IScheduler`, чтобы
  логика проверялась тестами на виртуальном времени; дефолтные планировщики Rx не использовать;
- каждая подписка в UI отписывается при уходе экрана.

На этом потоке сидят движок тревог, запись, панель и плеер — он и был заложен как точка
расширения ([план 4](android-plan-4-alerts-and-background.md)).

## Дефолты конфигурации колеса

`AppWheelConfig : IWheelConfig` — POCO с дефолтами (живут в `Resources/Raw/appsettings.json`,
секция `WheelConfig`):

```
GotwayNegative = "0", UseBetterPercents = false, HwPwm = false, CustomPercents = false,
CellVoltageTiltback = 330, RotationSpeed = 500, RotationVoltage = 840, PowerFactor = 90,
LightEnabled = false, UseRatio = false, AutoVoltage = true, GotwayVoltage = "1",
IsAlexovikFW = false
```

- `GotwayVoltage = "1"` соответствует паку 84 В / 20S тестового MTen3 — не менять.
- Экземпляр **один, общий и мутабельный**: декодеры пишут в него (`HwPwm`, `LightEnabled`,
  `IsAlexovikFW`), копия сломает логику.
- Значения — как у WheelLog; своё поведение — только настройкой и с записью в «Отклонения от
  оригинала» (AGENTS.md).

## Пять герц — темп прошивки, а не ограничение приложения

Измерено на живом Sherman L: **данные 5,0 Гц, сырые BLE-кадры 23,5 Гц** (~4,7 кадра на пакет
телеметрии). Записи подтверждают то же для обоих протоколов: MTen3 — 4,2 Гц, Sherman L — 5,1 Гц;
столько же давал и Windows-клиент.

Чаще колесо просто не отправляет: ни «сырые» вызовы, ни обход биндингов, ни другой транспорт
частоту не поднимут. Что со стороны телефона действительно помогает —
`RequestConnectionPriority(High)` после подключения: пакетов не добавляет, но убирает ожидание
между готовым пакетом и его приёмом, то есть уменьшает задержку показаний (в логе —
`Ble.HighPriorityRequested True`).

Следствие для тревог: чувствительность к всплескам ШИМ обеспечивается не частотой опроса, а
максимумом за скользящее окно ([план 4 §3.1](android-plan-4-alerts-and-background.md)) — ни один
пришедший снэпшот не теряется, даже если экран перерисовать не успел.

## Подводные камни BLE

- **CCCD `0x2902`** обязателен после подписки на характеристику. Симптом пропуска: подключились,
  ошибок нет, `DataReceived` молчит.
- **Запись длиннее MTU−3 не отвергается — она молча обрезается.** При MTU по умолчанию (23) в
  запись влезает 20 байт; стек Android отправит первые 20 и доложит об успехе. Симптом: в журнале
  `Cmd.Sent`, а колесо не отвечает вовсе. Стоило одного выезда: команды InMotion V1 — 22 байта, и
  V8F не отдал ни кадра телеметрии (07.08.2026). Поэтому `AndroidBleClient` просит MTU 517, а
  команда, которая всё же не влезла, валится `WriteTooLongException` вместо тихой отправки огрызка.
- **`OnConnectionStateChange` отдаёт коды HCI, а привязка зовёт их именами ATT.** `8` — таймаут
  супервизии линка (колесо уехало или выключилось), но печатается как `InsufficientAuthorization`.
  В журнале рядом с именем стоит число — верить числу.
- **Геолокация на Android ≤ 11** должна быть включена в системе, иначе `startScan` молча не
  вернёт ни одного результата.
- **`gatt.Close()`** обязателен при отключении.
- **Скан во время подключения** мешает установлению связи — останавливать до `ConnectAsync`.
- **MAC в `GetRemoteDevice` — только верхний регистр**, иначе `IllegalArgumentException`.
- **Veteran-распаковщик собирает пакет из нескольких кадров** и сбрасывает недособранное по
  таймауту реального времени — кадры должны идти подряд, как приходят по BLE.
- **У Begode/MTen3 более старый Bluetooth-стек**: на Windows потребовались ретраи
  GATT-discovery (`WindowsBleClient`); если discovery падает на Android — лечится повтором
  через ~500 мс.
- **PWM у Begode считается программно** (аппаратного значения нет) — это нормально.
- Поля `TelemetrySnapshot` — сырой fixed-point с парными «человеческими» свойствами
  (`SpeedRaw` / `SpeedKmh`); в UI выводить человеческие.
