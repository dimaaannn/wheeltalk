# План 1: базовая логика Android-приложения WheelTalk (.NET MAUI)

> ## ✅ ВЫПОЛНЕНО
> Приложение собрано, стоит на телефоне, проверено на живом Sherman L: скан находит колёса,
> подключение работает, телеметрия декодируется, потеря связи отображается, повторное
> подключение поднимается. Гейты T1–T5 пройдены на железе.
>
> Отклонения от плана, принятые по ходу: экран скана перестал быть стартовым (адрес колеса
> уехал в конфиг, приложение подключается само), троттлинг вывода убран за ненадобностью
> (см. §5.1), минимальная версия Android поднята с 21 до 28. Дальше — [План 3](android-plan-3-main-screen.md).
>
> **Исторический (30.07.2026).** Раздел §1 «не пересматривать» пересмотрен почти целиком:
> 29.07.2026 UI переписан с MAUI на голый Android ([план 12](android-plan-12-native-rewrite.md)) —
> боевое приложение `WheelTalk.Droid` (`com.wheeltalk.droid`), разметка кодом, отрисовка по
> vsync. Живые куски — §2.1 (поток телеметрии), §3.1 (дефолты `IWheelConfig`), §5.1 (5 Гц —
> темп прошивки) и §6 (подводные камни BLE) — вынесены в
> [telemetry-and-ble-reference.md](telemetry-and-ble-reference.md); сопровождается он, а не
> этот план.

> **Тип задачи:** реализация нового кода (MAUI-каркас + Android BLE-адаптер поверх готового ядра).
> **Ветка:** `android` (уже создана, работать в ней).
> **Цель:** приложение на телефоне: кнопка сканирования → список BLE-устройств с именами →
> тап по устройству подключает → экран с сеткой «краткое имя : значение» по всей телеметрии.
>
> **Место в серии:** это фундамент. [План 2](android-plan-2-ui-analysis.md) — анализ UI
> оригинального WheelLog, [План 3](android-plan-3-main-screen.md) — заглавный экран поверх
> того, что построено здесь. Красивый UI — задача плана 3; здесь достаточно работающего.

Это **техническое** приложение — проверка того, что портированное ядро работает на Android
с реальным колесом. Требуется работающая цепочка BLE → декодер → экран, а не дизайн.
