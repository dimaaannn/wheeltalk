# Требования к адаптивной разметке

> **Подтверждено владельцем 29.07.2026.** Требования действуют для всех нативных экранов.

> **Тип документа:** требования к вёрстке нативных экранов (`WheelTalk.Droid`,
> `WheelTalk.Dashboard.Droid`). Писано при переписывании с MAUI ([план 12](android-plan-12-native-rewrite.md));
> исходные решения по панели — [dashboard-feedback.md](dashboard-feedback.md).
> Повод: приложение проектируется под раздачу райдерам, а у райдеров «иногда используются
> маленькие телефоны» (владелец, 29.07.2026). Свой парк: BV6600 720×1440 (~360×720 dp),
> эмулятор Pixel 5 (~393×851 dp).

## 0. Главный принцип: прятать, а не мельчить

Панель — прибор, у прибора есть минимальный читаемый размер (принятое решение: кегли по
ISO 15008, минимум 12′ угловых). Поэтому при нехватке места элементы **скрываются по приоритету,
а не уменьшаются ниже порога читаемости**. Нечитаемый прибор хуже отсутствующего: он занимает
место и создаёт иллюзию контроля.

Приоритет на главном экране, от несжимаемого к первому кандидату на вылет:

1. **Цифра скорости** — не сжимается; её кегль растёт от освободившегося места, не наоборот.
2. **Ленты** (окно значения, цветные полосы, след) — сужаются до пола (см. §2), дальше не жмутся.
3. **Подписи делений лент** — прореживаются (реже подписанные риски), потом исчезают; сами риски
   остаются. **Не сделано** (30.07.2026): в коде нет ни прореживания, ни порога — требование в
   силе, реализации нет.
4. **Справочные пары центра** — уже прячутся по условию (`HideExtrasAbove`); на узких экранах
   порог срабатывает раньше, на самых узких пар две вместо четырёх (связано с принятой
   доработкой кеглей по ISO — место торгуется здесь же).
   Сделано, с уточнением (30.07.2026): порог в коде — не по ширине экрана, а по влезаемости
   строк в высоту центра (`SpeedBlockDrawable.cs:106-115`).
5. ~~**Ряд кнопок** — первый кандидат: владелец уже заметил, что кнопки едят ценное место;
   компоновка пересматривается на стенде (задача прототипирования). До того — кнопки не ниже
   48 dp касания, но и не жирнее необходимого.~~
   **Снято** (30.07.2026): ряда кнопок больше нет — его заменила шторка команд
   ([quick-commands-design.md](quick-commands-design.md)), прятать стало нечего.

Десятые скорости прячутся по уже принятому правилу (выше порога скорости) — на узких экранах
дополнительно по месту.

## 1. Единицы

- **Всё в dp, литералов в px нет.** Порт панели уже умножает константы на плотность —
  это правило, а не удобство.
- **Панель рисует размеры в dp, НЕ в sp.** Системный масштаб шрифта (доступность) не должен
  ломать выверенные пропорции прибора: панель — не текст, а шкала. Это осознанное отступление
  от рекомендаций доступности, и оно компенсируется собственной настройкой размера в
  «Отображении» (уже есть у кеглей панели).
- **Все остальные экраны (настройки, списки, телеметрия) — текст в sp**, уважают системный
  масштаб; разметка обязана переживать fontScale 1,3 без обрезаний (проверка входит в гейт §5).

## 2. Опорные ширины и полы

Опорная ширина разработки — **360 dp** (на ней сняты все цены: ленты 88 dp, центр 152 dp,
скорость 72/140 кегль — прогон 2; после расширения лент цена ленты изменилась — доля
`TapeShare` 28 % от ширины, на 360 dp это ~101 dp). Требования по диапазону:

| Ширина экрана | Поведение |
|---|---|
| ≥ 400 dp | Ленты и центр растут пропорционально, но с потолком: суммарная ширина контента ≤ 480 dp, дальше — поля. Панель не «размазывается» по планшету |
| 360–400 dp | Эталон, всё как измерено |
| 320–360 dp | Ленты сужаются вместе с экраном (доля `TapeShare`, пола нет — см. ниже); справочные пары — две; подписи делений прореживаются (не сделано, §0 п.3) |
| < 320 dp | Не поддерживается (нет таких устройств в обороте среди целевых); приложение не падает, панель живёт по правилам ступени 320 с обрезкой полей |

~~Пол ленты 72 dp — гипотеза; уточняется на стенде глазами, как и всё в dashboard-feedback.~~
Пола в коде нет (30.07.2026): лента — всегда доля `TapeShare` (28 %), сужается без нижней
границы; гипотеза пола не прижилась.
**Плотность шкалы (12 dp на процент) не меняется с шириной** — видимый диапазон ±26 % может
сокращаться, это уже принято («концы шкалы нужны, чтобы она не обрывалась, а не чтобы на них
смотрели»).

## 3. Ориентация и мультиокно

- **Главный экран — портрет, фиксированный.** Крепление на руле/запястье вертикальное; ландшафт
  панели — отдельная работа со своей компоновкой, не растяжение этой (в перспективу, причины
  пока нет).
  > **Расхождение с кодом — прав документ, недоделан код** (30.07.2026): `ScreenOrientation` в
  > коде не задан, зато объявлен `ConfigChanges.Orientation|ScreenSize` — Activity при повороте
  > не пересоздаётся, а потолок ширины считается один раз при сборке разметки с обоснованием
  > «портрет — §3». Итог: в ландшафте потолок не пересчитывается. Дефект кода, требует решения
  > владельца: либо честно зафиксировать портрет, либо пересчитывать при повороте.
- Остальные экраны ориентацию не фиксируют — обычные списки, им всё равно.
- **Split-screen / свободные окна:** не оптимизируем, но не падаем — панель сжимается по
  правилам §2, при высоте меньше ~400 dp прячется ряд кнопок (там уже есть полоса состояния
  для навигации). Android 12+ может навязать resizable — деградация обязана быть достойной.

## 4. Системные отступы: edge-to-edge, вырезы, жесты

С targetSdk 35 edge-to-edge принудителен, поэтому сразу верстаем правильно:

- Все экраны применяют **WindowInsets**: полоса состояния приложения начинается ниже системного
  статус-бара/выреза, ряд кнопок — выше зоны жестовой навигации. Ничего интерактивного под
  системными зонами.
- **Фон за системными барами** — фон панели (тёмный), не белые полосы.
- Вырезы (cutout): контент панели в вырез не заходит (`ShortEdges` не используем — прибору
  нечего делать под камерой); фон — заходит.
- KeepScreenOn на главном экране — уже есть, остаётся.

## 5. Как проверяется (гейт адаптивности)

Матрица конфигураций на эмуляторе (resizable AVD или несколько профилей), на одном кадре реплея:

| Конфигурация | Что проверяем |
|---|---|
| 320×640 dp | Ступень «маленький телефон»: полы лент, две пары, читаемость |
| 360×720 dp | Эталон (соответствует BV6600) |
| 393×851 dp | Pixel 5 — текущий эмулятор |
| ~600 dp ширины | Потолок 480 dp работает, панель не размазана |
| fontScale 1,3 | Панель не изменилась (dp); настройки/списки — без обрезаний |
| Жестовая и кнопочная навигация | Ряд кнопок не перекрыт |

Скриншоты матрицы складываются рядом со скриншотами приёмки. Проверка — глазами владельца,
как и вся приёмка панели.

> **Статус** (30.07.2026): гейт не прогонялся — ни пройден, ни отложен явным решением; матрицы
> скриншотов нет.

## 6. Что адаптивностью НЕ является (не делаем)

- Отдельные layout-ресурсы на каждую диагональ (`layout-sw600dp` и т.п.) — панель рисуется
  канвой от фактического размера, ей ресурсные вилки не нужны; спискам хватает одного макета.
- Планшетные двухпанельные компоновки — устройства-цели: телефон на руле/запястье.
- Ландшафт панели — до появления причины.
- Динамический пересчёт разметки на ходу от значений телеметрии — «прыгающую разметку не
  делаем» (решение владельца). Все пороги скрытия — по размеру экрана и настройкам, не по
  скорости кадра.
