# WheelTalk

Приложение для моноколеса под Android: показывает телеметрию, предупреждает о выходе на предел,
пишет журнал поездки. Ядро — порт декодеров [WheelLog.Android](https://github.com/Wheellog/Wheellog.Android)
на C# / .NET 10.

> **Приложение для личного пользования.** Оно ездит с колесом каждый день и сделано всерьёз, но
> сделано под себя: магазина, установщика и автообновления нет, APK ставится вручную, а API и схема
> базы меняются без оглядки на совместимость.

> **Не единственный источник правды на дороге.** Пороги тревог, расчёт ШИМ и проценты заряда взяты
> у WheelLog, но проверены далеко не на всех колёсах — на большинстве не проверены вовсе. Полагаться
> на цифры чужого колеса как на показания приборной панели нельзя.

## Что умеет

- **Опознаёт колесо само** — по дереву GATT и первому кадру, протокол руками не выбирают.
- **Приборная панель** — две ленты по краям (ШИМ и напряжение) и цифра скорости; полные показания
  таблицей на отдельном экране.
- **Тревоги** по ШИМ и скорости: звук, вибрация, вспышка камеры и полосы на панели.
- **Журнал поездки** в формате WheelLog (CSV) плюс сырой дамп BLE; телеметрия ведётся в SQLite,
  CSV — экспорт из неё.
- **Работа с погашенным экраном** — foreground-сервис, переподключение при обрыве.
- **Проигрывание записанной поездки вместо колеса** — интерфейс отлаживается без выезда, в том
  числе на эмуляторе, где Bluetooth-радио нет вовсе.
- **Устройства-посредники** («третий глаз») опознаются, но живого посредника у автора нет —
  проверено только тестами.

## Поддерживаемые протоколы

| Протокол | Колёса | Как проверен |
|---|---|---|
| Veteran | Sherman L | На живом колесе |
| Gotway / Begode | MTen3 | На живом колесе |
| KingSong | — | Только фикстурами оригинала |
| InMotion V1 | — | Фикстурами и сырыми BLE-дампами |
| InMotion V2 | 11 моделей | Только фикстурами оригинала |

Ninebot опознаётся по имени, но не поддержан: подключение прекращается с объяснением.

## Устройство репозитория

|---|---|
| `WheelTalk.Core` | Ядро: контракты, декодеры пяти протоколов, сессия, тревоги, настройки, плеер. Без платформенных зависимостей (`net10.0`) |
| `WheelTalk.Storage` | SQLite: поездки и слои настроек |

## Сборка

Нужен **.NET 10 SDK**; для Android-проектов — рабочая нагрузка `android`:

```bash
dotnet workload install android
```

Сборка целиком и тесты:

```bash
dotnet build WheelTalk.slnx
```

```bash
dotnet test WheelTalk.Tests
```

Боевой APK (одна архитектура, `arm64-v8a`, минимум Android 9 / API 28):

```bash
dotnet publish WheelTalk.Droid -c Release -f net10.0-android
```

Результат — `WheelTalk.Droid/bin/Release/net10.0-android/publish/com.wheeltalk.droid-Signed.apk`,
около 13 МБ. Без файла `WheelTalk.Droid/signing.props` (он в репозиторий не берётся, образец —
`signing.props.example` рядом) Release подписывается отладочным ключом: репозиторий остаётся
собираемым на чужой машине.

## Запуск без колеса

Настройка `Replay:DumpFile` подставляет вместо BLE проигрыватель сырого дампа. Дамп кладётся во
внешний каталог приложения:

```bash
adb push replay/mten3-calm-ride.csv /sdcard/Android/data/com.wheeltalk.droid/files/ride.csv
```

Дальше в `usersettings.json`: `{"Replay":{"DumpFile":"ride.csv","Speed":0.25}}`. Что в каком файле
записи — [replay/README.md](replay/README.md); подробный рецепт, включая эмулятор, — в
[AGENTS.md](AGENTS.md), раздел «Как гонять приложение без колеса».

## Отношение к WheelLog

Ядро — построчный порт декодеров WheelLog, и это осознанная опора, а не заимствование по случаю:
WheelLog стал фактическим стандартом, райдеры знают, что означают его цифры, на его CSV завязаны
сторонние сервисы. Поэтому формулы (ШИМ, проценты заряда, модель тревог), их значения по умолчанию
и формат журналов берутся оттуда, а не придумываются заново.

Расхождения есть, и все они перечислены с причинами в [AGENTS.md](AGENTS.md), раздел «Отклонения
от оригинала» — от палитры панели, различимой при дейтеранопии, до непортированных семейств тревог.
