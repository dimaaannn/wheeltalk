# Нарезка для отладки

Куски настоящих поездок, вырезанные из сырых дампов 28.07.2026 — по одному характерному
состоянию в каждом. Приложение проигрывает их вместо колеса: настройка `Replay:DumpFile`,
рецепт целиком — в [AGENTS.md](../AGENTS.md), раздел «Как гонять приложение без колеса».

Формат тот же, что пишет приложение: `HH:mm:ss.fff,<hex>`, одна строка на BLE-нотификацию.
Файл проигрывается по кругу, так что короткого куска хватает надолго.

## InMotion V1/V2 — настройка протокола реплея

У InMotion V1 и V2 кадры одинаковые (`AA AA`), по заголовку их не развести — а у записанной
поездки нет дерева GATT, по которому это делает живое подключение (план 21 §0.2). Для дампа
InMotion протокол называется настройкой `Replay:Protocol` (`"InMotion"` / `"InMotionV2"`) —
без неё `AutoDecoder` попытается опознать кадры по заголовку и не узнает `AA AA` ни за один, ни за
другой, и дамп останется без телеметрии. Для всех остальных протоколов (Veteran/Begode/KingSong)
настройка не нужна и должна оставаться пустой — они называют себя сами по заголовку кадра.

Своих нарезок для InMotion в этой папке пока нет — живого InMotion у владельца нет, и нарезать
характерные состояния не с чего. Единственные записи — `WheelTalk.Tests/Fixtures/RAW_inmotion_*.csv`
(из оригинала WheelLog, `Wheellog.Android/app/src/test/resources/`): полные сырые дампы, не
нарезка по состояниям, и туда же, а не сюда, они и должны попадать при появлении реальной
записи с колеса.
